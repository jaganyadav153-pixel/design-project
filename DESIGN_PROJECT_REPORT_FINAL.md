# ABSTRACT

First-year Computer Science and Engineering students must choose among more than twenty-five distinct career tracks, including Artificial Intelligence, Machine Learning, Data Science, Cybersecurity, Cloud Computing, Full-Stack Development, and emerging areas such as Blockchain, Robotics, and Quantum Computing. Conventional counselling in colleges is manual, senior-dependent, English-only, and limited to branch selection rather than domain selection within CSE. As a result, students depend on peer pressure, social-media hype, or salary rumours, which leads to mid-course track switching, skill mismatch, and placement stress.

This project presents **GuidanceAI**, an AI-powered virtual counsellor for first-year CSE students. A student completes a 15-question aptitude and interest quiz with four options per question and enters marks in four subjects. The system produces the **Top-3 personalised CSE domain recommendations across 25 tracks (Atlas 25: AI to Quantum)** with confidence percentage, explanation, skill-gap radar, 36-week roadmap, mini-course with test, per-domain resource vault, and parent-friendly report in ten languages with voice readout.

The system uses a dual frontend: a zero-install vanilla HTML with Tailwind CSS single-page site that runs by double-clicking `index.html` (offline capable) and a React with Vite and Tailwind alternative scaffold. The backend is Django REST hosted on Render, with endpoints for prediction, domains, resources, vault, feedback, and chatbot. The machine learning pipeline uses `ml/dataset.csv` with 750 synthetic records (30 per domain across 25 domains, 11 features plus label), StandardScaler for normalisation, Principal Component Analysis for dimensionality reduction from 11 to 10 components retaining 95 percent variance, and Random Forest with 100 trees as the primary model. Random Forest achieved **89 percent accuracy (cross-validation 82 percent)**, compared with Decision Tree at 64 percent and K-Nearest Neighbours at 82 percent. The trained artefacts are stored in `backend/ml_service/model.pkl`. A deterministic weighted-ensemble fallback in the frontend guarantees identical Top-1 prediction when the backend is offline.

Evaluation confirms Top-1 accuracy of 89 percent on the held-out set, Top-3 recommendation with explanation, live radar and what-if analysis, and successful demonstration of the complete flow: quiz to radar to roadmap to Telugu parent voice report to immersive 3D domain handbook. The project demonstrates that machine learning combined with full-stack engineering and multilingual design can deliver practical and inclusive academic counselling.

**Keywords:** Career Guidance, Domain Recommender System, Random Forest, Principal Component Analysis, Django REST Framework, Multilingual Speech Synthesis, Skill Radar, Progressive Web App.

# 1. INTRODUCTION

## 1.1 Overview

Computer Science and Engineering enrolment in India exceeds five lakh students per year. After admission, the most difficult question for a first-year student is not how to code, but which direction to pursue. The CSE discipline now contains twenty-five distinct and viable career tracks. The Atlas 25 taxonomy used in this project groups them as: Intelligence and Data (6) — Artificial Intelligence, Machine Learning, Data Science, Big Data, Computer Vision, Natural Language Processing; Build and Experience (5) — Web Development, Mobile App Development, Software Engineering, Game Development, Human-Computer Interaction; Core Systems (8) — Cybersecurity, Cloud Computing, Computer Networks, Database Management Systems, Operating Systems, Computer Architecture, DevOps, Distributed Systems; Frontier Technology (6) — Internet of Things, Blockchain, Robotics, Augmented Reality / Virtual Reality, Embedded Systems, Quantum Computing. Each track differs in mathematical intensity, creativity demand, tools, salary band from 5 to 20 LPA, and preparation path.

GuidanceAI is designed as a virtual counsellor for this decision. The student completes a 15-question quiz covering logical reasoning, mathematical aptitude, creativity, and interest in security, cloud, data, operating systems, coding, emerging trends, and social interaction, with each answer scored from 1 to 4, and enters marks in Mathematics, Physics, Programming, and English on a scale of 0 to 100. The backend normalises the inputs with StandardScaler, reduces dimensions with PCA from 11 to 10 components, applies Random Forest classification, and returns the Top-3 domains with confidence scores and a natural-language explanation such as High logic 4 of 4 with Mathematics 92 indicates Artificial Intelligence as optimal. The frontend renders confidence bars, a Chart.js skill-gap radar, a what-if simulator with sliders, a 36-week handbook roadmap, a mini-course with three lessons per domain with test and certificate, vault suggestions, and a parent report.

The implementation is intentionally dual-frontend and deployment-ready. The main site is vanilla HTML with Tailwind CSS via CDN in `index.html`, which works by double-clicking without installation and functions offline through a service worker and a weighted-ensemble fallback. The alternative scaffold is React with Vite and Tailwind in `frontend/` with proxy to the Django backend. The backend in `backend/` is Django REST Framework with SQLite for development and PostgreSQL readiness for production, deployed with Gunicorn on Render, while the frontend is deployed on Vercel. Multilingual support covers ten languages — English, Telugu, Hindi, Tamil, Kannada, Malayalam, Marathi, Bengali, Gujarati, and Urdu — with Noto fonts, right-to-left support for Urdu, and Web Speech API for text-to-speech voice readout and speech-to-text input.

## 1.2 Motivation for the project

The motivation for GuidanceAI arises from seven observed problems in first-year counselling.

1. Decision paralysis in Year 1. Students select Artificial Intelligence because it trends on social media and later discover heavy mathematics and statistics requirements. A data-driven Top-3 with confidence and a what-if simulator prevents costly mid-course switching.
2. Exclusion of parents. A large fraction of parents in Tier-2 and Tier-3 colleges are not comfortable with English. A Telugu or Hindi voice report with printable PDF allows a parent to understand the recommendation, salary band, and 36-week plan without English dependence.
3. Lack of teacher visibility. Heads of departments need batch-level analytics to allocate laboratories and remedial classes. A teacher dashboard with distribution bar charts and at-risk flags addresses this need.
4. Absence of actionable next steps. A label such as You should learn Cloud is insufficient. A 36-week phased roadmap with curated NPTEL, Coursera, and YouTube resources, mini-course, test, and per-domain vault makes the recommendation executable from day one.
5. Need for reproducible machine learning evidence. Viva and evaluation require an open dataset, training script, metrics file, and saved model, rather than a black-box API. This project provides `ml/dataset.csv`, `ml/train_model.py`, `ml/metrics.json`, and `backend/ml_service/model.pkl`.
6. Need for offline-first demonstration. College laboratories frequently have weak internet connectivity. The main site with service-worker caching, localStorage persistence, and weighted fallback ensures the quiz and demo continue without backend connectivity.
7. Gaps in published work. Prior systems reviewed in Chapter 2 lack parent involvement, multilingual support, visualisation, mini-courses, and batch analytics. GuidanceAI is designed to fill all these gaps in one integrated system.

## 1.3 Problem Definition and Scenarios

Problem Definition. Develop an AI-powered virtual counsellor that maps a 15-dimensional quiz vector plus a 4-dimensional marks vector to 25 CSE domains with calibrated confidence, explains the recommendation with skill visualisation, grounds it in a 36-week actionable roadmap with curated resources and vault storage, and communicates it appropriately to three stakeholders — student through interactive UI with gamification, parent through vernacular report with voice, and teacher through batch analytics — while remaining offline-capable, deployable on Vercel with Render, and evaluable through open dataset, metrics, and model artefacts.

Representative scenarios are as follows.

A student with Mathematics 58 and creativity 4 of 4 receives Human-Computer Interaction 88 percent, Game Development 81 percent, and Web Development 79 percent, with an explicit low-mathematics and high-creativity path from UX basics to Figma to user research to prototype, instead of being forced toward Artificial Intelligence.

6. Vault collector. A student drops `DBMS_Notes.pdf` into `public/vault/dbms/notes/`. The Explorer card badge updates from Vault 0 to Vault 1. After deployment, the file is accessible at the corresponding public vault URL.

8. Chatbot follow-up. A student asks Roadmap for HCI in Tamil and receives UX Basics to Figma to User Research to Prototype with vault tip, in the selected language.

# 2. LITERATURE REVIEW

## 2.1 Introduction

Academic counselling technology has evolved from manual faculty advice to rule-based expert systems, web portals that rank colleges, machine learning branch predictors, and large-language-model chatbots. Personalisation, vernacular access, and progress tracking have been shown to improve adherence and learning outcomes in healthcare-reminder and e-learning literature. However, CSE domain guidance remains shallow. Most portals rank colleges rather than domains within CSE. Most machine learning papers predict branch such as CSE versus Electronics, rather than track such as Artificial Intelligence versus Human-Computer Interaction versus Quantum Computing. Multilingual parent involvement is almost absent. This review examines career counselling systems, branch predictors, course recommenders, voice-based reminder systems, and chatbot systems to position the contribution of GuidanceAI.

## 2.2 Literature review

### 2.2.1 AI-based career counselling at branch level

A 2025 study in the AI Journal of Multidisciplinary Research proposed an AI-based counselling system that predicts engineering branch from marks using decision trees. Its strength is simplicity and interpretability. Its limitation is scope: only four to six branches, no domain depth within CSE, English-only output, no parent dashboard, and no roadmap. The takeaway for this project is the need for domain-level prediction across 25 tracks with vernacular reporting and a phased roadmap, both implemented in GuidanceAI through the Telugu voice parent report and the 36-week handbook.

### 2.2.2 Branch prediction with Random Forest and KNN

A 2022 study in the International Journal of Research and Analytical Reviews compared Random Forest and K-Nearest Neighbours for branch allocation with accuracy near 78 percent. Its strength is model-comparison methodology with cross-validation, which is reused in `ml/train_model.py` and `ml/metrics.json`. Its limitation is that it predicts only branch with six labels, without interest signals, visualisation, or mini-courses. The takeaway is to adopt the comparison and reporting discipline but extend it to 25 labels with radar visualisation, mini-course, and test.

### 2.2.3 E-learning recommender with NPTEL and Coursera

A 2024 study in the Journal of Emerging Technologies and Innovative Research recommended courses from interest keywords using curated NPTEL and Coursera mappings. Its strength is the curation methodology, reused in the Resource Hub and the `Resource` model with filtering by domain, type, and language. Its limitation is the absence of aptitude and marks-based machine learning filtering, visualisation, and vault storage. The takeaway is to integrate curation with the machine learning filter, so resources are suggested for the predicted Top-3 rather than generic keywords.

### 2.2.4 Voice-based reminder and text-to-speech systems

Voice-based reminder literature using text-to-speech libraries such as pyttsx3 shows that audible announcements improve adherence for elderly users and users with reading difficulty. Smart pill dispensers add compartment hardware and sensors but increase cost and complexity. The limitation of conventional voice systems is generic messaging without user-specific machine learning personalisation. The takeaway for GuidanceAI is to reuse the voice insight through browser-native Web Speech API for parent voice reports in ten languages without additional hardware, and to reuse status-recording patterns as lesson-completion and XP tracking.

### 2.2.5 Chatbot with retrieval and voice in education

Retrieval-augmented chatbots over course documents with speech input and output improve engagement when grounded in institutional content. Unconstrained chatbots hallucinate. The takeaway is implemented as `POST /api/chat`, which builds grounded context from 25 domain blurbs and live vault file listings, supports multi-turn history with anaphora resolution for queries such as its salary, uses Claude 3.5 Sonnet when an API key is configured, and falls back to offline TF-IDF cosine similarity otherwise, with input sanitisation against prompt injection.

### 2.2.6 Resource hub and portfolio systems

Portfolio and file-slot systems show that students retain more when each track has a dedicated place for notes, videos, projects, and assignments. The takeaway is the per-domain vault with 100 folders in `public/vault/` mirrored privately in `uploads/domains/`, with UI slots, localStorage persistence, and backend API listing used by both explorer and chatbot.

## 2.3 Conclusion/Gap

Seven consistent gaps remain across existing methods. First, branch prediction instead of domain prediction: prior machine learning predicts CSE versus other branches, while none covers 25 tracks within CSE with skills, salary, and roadmap per track. Second, absence of parent and vernacular coverage: English-only reports exclude parents, with no voice readout. Third, absence of visualisation: no radar or what-if analysis to show why Artificial Intelligence ranks above Operating Systems for a given student. Fourth, absence of actionable roadmaps: recommendations stop at a label without a phased plan, mini-course, test, or vault. Fifth, absence of batch analytics for teachers: no at-risk flags or cohort distribution. Sixth, offline fragility: cloud-only demos fail in laboratories without a fallback or progressive web app. Seventh, closed datasets: no open CSV, metrics, or saved model for an evaluator to verify accuracy. GuidanceAI is designed to fill all seven gaps with 25-way Random Forest at 89 percent accuracy with open artefacts, ten-language voice parent reports, Chart.js radar with what-if simulation, 36-week handbooks with mini-courses and vaults, teacher analytics, offline ensemble with service worker, and fully open code and documentation.

# 3. PROJECT DESCRIPTION

## 3.1 Objective of the Design Project work

The main objective is to develop an intelligent, user-friendly, and deployable virtual counsellor that helps first-year CSE students select and prepare for a suitable domain. The specific objectives are as follows.

1. To implement face-free, quiz-based user profiling with 15 aptitude and interest responses scored 1 to 4 plus marks in four subjects.
2. To implement a 25-way domain recommender that returns Top-3 domains with confidence and explanation using Random Forest at 89 percent accuracy with PCA, with a deterministic weighted fallback for offline use.
3. To provide an Atlas 25 explorer with grouping, search, sort, compare up to three tracks, command palette, and per-domain vault.
4. To automate guidance with a 36-week handbook roadmap per domain, four-year timeline, mini-course with three lessons per domain, test, certificate, and experience points.
5. To provide multilingual voice reports in ten languages with Noto fonts, right-to-left support for Urdu, text-to-speech readout, and printable parent PDF.
6. To manage knowledge with Django models for student profile, quiz response, prediction, domain, resource, and feedback, plus a curated Resource Hub and a 100-folder vault system.
7. To record progress with XP, streak, badges, bookmarks, lesson completion, and feedback ratings in localStorage and database.
8. To reduce wrong-track selection and hype-driven switching through radar visualisation, what-if analysis, and teacher at-risk flags.

## 3.2 Existing System

1. Manual counselling. Faculty or senior advice in one-to-one meetings. It is non-scalable, коллежи-dependent, and biased toward the counsellor's own domain.
2. Portal rank lists. College-ranking portals rank institutions, not domains. Articles comparing AI versus ML are generic and not personalised.
3. Time-based reminder applications. Predefined alarms and notifications remind at a fixed time without mapping aptitude to domain.
4. Mobile application reminders. Smartphone alerts store medicine or task details but depend on continuous phone interaction and provide no domain intelligence.
5. Branch predictors. Machine learning models with four to six labels use marks only, without creativity or interest signals, and stop at branch level.
6. Voice-only notifications. Text-to-speech announcements without personalisation provide the same message irrespective of user profile.
7. IoT and RFID systems. Sensor, microcontroller, and reader-based monitoring allow remote tracking but require dedicated hardware, continuous internet, and higher cost.
8. Smart dispensers. Automated compartment release with alarms reduces manual selection but adds mechanical complexity and cost, unsuitable for counselling.
9. Course recommenders. Keyword-to-course mapping suggests NPTEL or Coursera courses without aptitude filtering or visualisation.
10. Limited stakeholder coverage. Existing solutions are student-only, English-only, without parent or teacher views, batch analytics, or offline guarantees.

## 3.3 Proposed System

Face-free quiz profiling. The proposed system uses a 15-question quiz plus four subject marks instead of camera biometrics, preserving privacy with no biometric storage. Each registered profile has separate quiz responses and marks.

Personalised Top-3 prediction. Each prediction maps the 15 responses and four marks through StandardScaler, PCA, and Random Forest to 25 domains. The API contract is `POST /api/predict` with `{answers: [15 integers 1 to 4], marks: {math, phy, prog, eng}}` returning `{top, confidence, top3, explanation, model}`. When the saved model is unavailable, `weighted_predict()` with a 25 by 17 weight matrix identical between backend and frontend guarantees parity.

Automated roadmap and learning. The system generates the Top-3 with a 36-week handbook per domain in six phases, a four-year timeline from foundation to placement, three YouTube lessons per domain, a five-question test, XP with printable certificate, and vault links.

Voice and visual notifications. Recommendations are delivered through confidence bars, radar charts, toast notifications, vernacular text, voice announcements through Web Speech synthesis, and printable PDF for parents.

Multiple stakeholder support. Three dashboards serve student with XP and roadmap progress, parent with vernacular voice and PDF, and teacher with batch bar charts and at-risk flags.

Knowledge management. Django models store profiles, responses, predictions, domains with skills and roadmaps in JSON, resources with type, language, difficulty, URL, and rating, and feedback with rating. The Resource Hub filters by 25 domains, three source types, and two language groups, with bookmarking.

Progress recording. After each quiz, lesson, or test, XP, streak, badges, bookmarks, and feedback are stored in localStorage for offline use and in the database when online, maintaining a history of guidance activity.

Reduced confusion. Since each Top-3 is tied to the individual's quiz and marks with an explanation and radar, hype-driven selection and confusion between tracks are reduced, particularly for households where multiple students share a device.

Simple and user-friendly operation. The main site requires only a browser double-click. No installation, signup, camera calibration, or hardware assembly is needed. Urdu renders right-to-left automatically.

Scope for future enhancement. Mobile application, caregiver notifications, cloud analytics, advanced models, and proctored skill tests are planned and listed in Chapter 9.

## 3.4 Benefits of Proposed System

Personalised Top-3 with confidence instead of a generic list. Explainable output with radar and what-if analysis. Multilingual inclusion with ten languages and voice. Actionable guidance with roadmap, mini-course, test, and vault. Teacher insight with batch analytics and at-risk detection. Offline-first with PWA and weighted fallback. Open evidence with dataset, metrics, model, and file map. Zero-install demonstration with double-click execution. Privacy-first with no signup and local data. Deployable architecture with Vercel frontend and Render backend with CORS and security headers.

# 4. SYSTEM DESIGN

## 4.1 Architecture Diagram

The system design describes the overall structure, components, and interaction between modules. The system identifies student aptitude through quiz and marks, predicts domains through machine learning, retrieves handbook and resource knowledge, and delivers recommendations through visual, textual, and voice channels. It consists of modules for profiling, prediction, explorer, handbook, roadmap with mini-course, resource hub, vault, chatbot, dashboards, feedback, and progress tracking. The design focuses on single responsibility per folder, offline-first behaviour, API parity between online model and offline fallback, and stakeholder separation.

Figure 4.1 — System Architecture.

```
[Student / Parent / Teacher Browser]
  index.html, pages/*, assets/js/app.js, handbooks.js, domain.js
  frontend/src/* (React alternative with i18n in 10 languages)
        |  fetch /api/* with CORS to Render
        |  fallback to weighted ensemble when offline
        v
[Django REST API on Render — backend/api/views.py]
  POST /api/predict | GET /api/domains | GET /api/resources
  GET  /api/vault   | POST /api/feedback | POST /api/chat
        |
[ML Service — backend/ml_service/model.pkl + predictor.py]
  StandardScaler -> PCA (11 to 10, 95 percent variance)
  -> RandomForest (100 trees, 89 percent) / DT / KNN
        |
[Data Stores]
  SQLite (dev) / PostgreSQL (prod): StudentProfile, QuizResponse,
  Prediction, Domain, Resource, Feedback
  Static Vault: public/vault/<slug>/notes|videos|projects|assignments/
  Media Mirror: uploads/domains/<slug>/ (Django MEDIA_ROOT)
        |
[External Services]
  NPTEL / Coursera / YouTube embeds, Claude 3.5 Sonnet (optional),
  Web Speech TTS/STT, Vercel static hosting with _headers
```

Table 4.1 — Major Software Components.

| Explorer Module | Atlas 25 grid, grouping, search, sort, compare, palette | index.html, pages/explorer.html |
| Handbook Module | 25 handbooks with 18 sections, 3D renderer, charts, timeline | assets/js/handbooks.js, domain.js |

Data-Flow Sequence. Step 1: User interacts through the graphical interface and selects language and role. Step 2: Quiz responses and marks are validated and cached locally. Step 3: Frontend posts to `/api/predict`. Step 4: Backend validates 15 integers from 1 to 4 and marks from 0 to 100 with a 10 KB limit, loads the model, applies scaler and PCA and Random Forest predict_proba to obtain Top-3, or applies weighted fallback. Step 5: Frontend renders Top-3 cards, confidence bars, radar, explanation, roadmap link, and vault suggestion, and stores XP and prediction history. Step 6: Handbook page loads the selected domain handbook with 3D hero, demand charts, timeline, interview kit, and vault slots, with live vault listing from `/api/vault`. Step 7: Chat queries use grounded context with vault files and history to answer in the selected language with optional voice. Step 8: Dashboards aggregate progress, parent voice reads the vernacular summary, teacher view flags at-risk students. Step 9: Feedback is sanitised and stored with toast confirmation.

This integrated architecture provides an automated, personalised, explainable, and user-friendly approach to domain guidance with offline guarantees and deployment readiness.

# 5. PROJECT REQUIREMENTS
